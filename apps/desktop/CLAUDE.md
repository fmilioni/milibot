# Desktop (Electron)

## Main process (`src/main/`)

- Layout: `app/` (launch modes, lifecycle with tray and quit handling, `AppSettingsWatcher`, `i18n`), `daemon/` (`DaemonManager`, pure `command`), `ipc/`, `windows/`, `platform/` (login items, host probes, exec, `app-id`), `services/` (VNC bridge, notifications, design export, logging), `menus/`. `index.ts` only composes them; nothing else has import-time side effects.
- **IPC contract**: a channel is named once in `src/bridge/channels.ts` (zod-free: the sandboxed preload bundles it) and typed once in `src/bridge/contract.ts` (`MilibotBridge` is derived from it; the renderer imports it with `import type` only). The preload builds `window.milibot` from the channel maps (`preload/bridge.ts`); main registers every handler through `ipc/register.ts`, which `satisfies InvokeHandlers`, so a channel without a handler fails typecheck. New channel: name in `channels.ts`, entry in `contract.ts`, handler in the domain file under `ipc/`, and its window kinds in `channels.ts`'s surfaces.
- **Per-window surface**: `allowedChannels(kind)` decides what each window's preload exposes and `ipc/handle.ts` refuses the others, along with senders that are not the top frame of a registered window on the app's own page (`windows/trust.ts`). A method missing from a window's bridge is a `TypeError` in the page: check `window.milibot.windowKind` in code every window runs (`features/workspace/store/effects.ts`).
- **Windows** (`windows/`): all created by `create.ts` and kept in the `registry.ts` map (one per kind and key); closing a workspace's last window calls `closeWorkspace`. `hardening.ts` keeps every webContents on the app's page (no navigation away, http(s) popups sent to the browser, no `<webview>`); `permissions.ts` denies every permission except clipboard write and fullscreen: a new renderer API that needs one must be added there.
- The page never names a port or an arbitrary path: `openVnc` takes a bot and main asks the daemon for its port; `openPath` (`platform/host/open-path.ts`) only takes files the daemon exported for download, `revealPath` also paths under the data root, the built-in skills and the last backup.
- `AppSettingsWatcher` owns the app WebSocket (language and theme for menus, tray, dialogs and notifications) and feeds `NotificationCenter`, which follows every workspace's events without starting runtimes. Main-process strings in `app/i18n.ts`.
- Never test against the real system: `platform/login-item/mac.int.test.ts` uses a fake `launchctl`; setup hints come from the daemon's injected probe (`GET /host`).
- **Linux/Windows**: only macOS draws traffic lights over the content (`windows/chrome.ts`, the renderer's `mac:` variant). Closing the last window keeps the app in the tray (skipped on Linux without a StatusNotifierWatcher); its Quit stops the daemon. Daemon stop = `POST /shutdown`, falling back to SIGTERM on macOS/Linux only (a signal on Windows kills without cleanup). The login item starts the app with `--start-daemon`, which only ensures the daemon and exits, skipping the single-instance lock.
- Windows title bar: the renderer sends the background under the caption buttons (`setTitleBarOverlay`). To see it on Linux, force `windowChrome(…, 'win32')` and the preload `platform` locally, never commit that.
- **Design exports** (`services/design-export/`): the page is written to a temp file (embedded fonts are too big for a data: URL) and rendered in a hidden `offscreen: true` window; PNG through `webContents.debugger`, PDF from `shared/src/designs/print.ts` (same document as the daemon's). Copy as image uses the async `clipboard.write`. Single-frame exports live only in the frame's menu, never tied to the canvas selection.
- A `.mbdesign` given to the chat never becomes an attachment (`features/chat/attachment-store.ts` imports it). To test without the save panel: `electron-vite dev --inspect <port>` and replace `dialog.showSaveDialog` from the main inspector.

## Renderer (`src/renderer/src/`)

- **Layout**: `app/` (entry, window routing, boot, toasts, right panel, modal host), `api/` (typed client and event streams in `daemon.ts`, the query layer, `workspace-scope`), `ui/` (generic primitives), `features/<area>/` (components, hooks, `store.ts`, `api.ts`, pure `lib/`), `lib/` and `hooks/` (generic). Import across folders with `@/`, `./` only within a folder. `ui/`, `hooks/` and `lib/` never import `app/`, `api/` or features (eslint): they take data and callbacks; hooks and components bound to the app store live in `features/workspace/`.
- **App store** (`features/workspace/store/`, imported as `@/features/workspace/store`): one Zustand store built from `slices/` sharing `context.ts`. Workspace events go through the pure `applyWorkspaceEvent(state, event, now)` (`workspace-events.ts`) and `context.ts` runs what they set off.
- **Navigation**: `screen` is one union (`features/workspace/lib/navigation.ts`) and `navigate(target)` its only writer; the `open*`/`close*` actions are wrappers. `enterScreen` keeps the session rule (the right panel is saved in `restorePanel` and hidden while in sessions); `canvasScreenFor` keeps the canvas's way back (`backNav`/`back`). A pick that must not move the screen is `pickConversation`, not `selectConversation`. Setup is not a screen: `MainWindow` shows it while the workspace's `setup` isn't `done`.
- **Server data = TanStack Query**: keys in `api/queries.ts` (`['ws', workspaceId, area, …]`; invalidating a prefix refetches everything under it), `useApiQuery`/`useApiMutation`. Daemon calls live in `features/<area>/api.ts`, not in components. Events reach the cache through `api/cache-updates.ts`. A provider change has no event, so provider mutations invalidate `queryKeys.providers`, the one providers query every screen reads. A reconnect invalidates the whole workspace prefix. Stores keep client state and the caches events patch in place.
- **Workspace-scoped stores**: every action takes the `workspaceId` it works on (`useWorkspaceId()`); a store holding workspace data uses `createWorkspaceScope` (`api/workspace-scope.ts`: `forWorkspace` drops another workspace's data, `commit`/`isCurrent` for answers arriving after a switch).
- **Subscriptions are registered at boot**: importing a module has no side effects; `app/subscriptions.ts`'s `registerSubscriptions()` (called once from `app/main.tsx`) wires the stores' `applyEvent`s, cache updates, cross-store watchers and window effects. A new store that follows events adds itself there.
- **Zustand selectors** must return stable values: a fresh `[]` or object per call loops React.
- Model pickers: `features/providers/lib/models.ts` (`MODEL_DEFAULT` = null in the body; `effortForModel` drops an effort the new model doesn't take).
- **Reuse `ui/`** instead of re-implementing; dialogs are `Modal`; never a native `<select>` (`Select.tsx`/`MultiSelect.tsx`) or date input (`ui/DatePicker.tsx`). Anything floating is a `ui/floating/FloatingPortal` placed by `useAnchoredPosition`; Escape goes to the topmost `[data-menu]` layer first (`Modal` ignores it while one opened after it is on screen). `Popover.tsx`: pass the `trigger` element so clicking it toggles instead of closing and reopening. Sidebar ordering = shared `applySidebarMove`, board moves = shared `applyCardMove` (the daemon uses the same functions). Chat markdown renders without raw HTML.
- **Images in markdown**: the page can't load a markdown image (VM paths, CSP), so `Markdown` leaves images out unless given `renderImage`/`renderAsset` (`renderAsset` keeps `asset:` URLs, which react-markdown's default transform drops). Chat text passes the attachments whose VM path it shows (`features/chat/lib/inline-images.ts`). Full-size images open in `ui/ImagePreview.tsx` (`z-preview`, under tooltips).
- **StrictMode**: never reset state in an unmount cleanup (it fires under StrictMode); follow the screen instead, as `followSkillsScreen` does for the skills dialogs.
- **Design canvas** (`features/canvas/`): frames are the compiled page in an `<iframe sandbox="allow-same-origin" srcdoc>` inside a `translate+scale` world (`allow-same-origin` only lets the app measure `auto` heights; the page's CSP already blocks scripts). Pages are cached per `frameId\ntheme` with a version keyed by that theme's values (an identical string keeps the iframe). The canvas window boots with `boot({chat: false})` (selects no conversation, marks nothing read).
- Drafts (`lib/design-drafts.ts`) double-buffer their iframes with one load at a time and only the newest version waiting (`offerPage`/`pageLoaded`). Menu accelerators for ⌘+/⌘−/⌘0 were not verified against the canvas's `preventDefault` (CDP key events skip the menu).
- **Bot cursors** (`BotCursor.tsx`, `use-bot-cursors.ts`, `lib/bot-cursor.ts`): glide state lives in a map outside the ref callback (an inline ref is detached and reattached every render, so state kept there made the cursor jump); a bot that leaves the list stays rendered hidden so it fades out instead of unmounting. `.canvas-read-scan`'s CSS duration must equal `READ_SCAN_MS`. A draft's placed height lags the version that just loaded, so its spots are clamped only horizontally. Drawings (`draft.art`) never drive the bot's cursor (they get a `PenCursors.tsx` pen).
- **CLI engines**: the app branches on no engine id. Cards, setup rows, the login step, provider bodies and model lists come from `CLI_ENGINE_INFO`; texts are generic keys interpolating `cliTextParams(engine)` (`lib/cli-engines.ts`), except `settings.providers.cli.<engine>.note`. An engine with one auth mode gets no mode switch and the `missingAccount` wording. Error cards carry `cli_*` codes with `params.engine` (`cliErrorOf`). The settings card's sign-in mark comes from `GET /cli/:engine/login` (seconds for engines that start their CLI to answer); the stored plan only stands in while the VM gives no answer.
- **Setup** (`features/setup/`): the workflow is `use-setup-flow.ts` (keyed by workspace; `SetupScreen` only renders) over the pure `lib/setup-flow.ts`; the login step (one per CLI engine on a subscription, in `CLI_ENGINES` order) can go back to `providers`, the only backward transition (`SETUP_TRANSITIONS`). With the VM already running, step 1 saves the providers and sets `vm` instead of creating the machine.
- **Theme**: tokens as CSS variables in `styles.css` (`:root` light, `[data-theme=dark]`), exposed through `@theme inline`. No arbitrary font sizes, z-index numbers or hex colours in classNames (`test/design-tokens.test.ts`): use the font scale (size only, so pair with `leading-*`), `bg-scrim*`, `screen-*` colours for surfaces dark in both themes, and the z-index roles. Conditional classNames go through `cn` (no conflict merging). The `index.html` CSP allows no external network (fonts through `@fontsource`).
- Focus: `focus-ring` for controls; rows inside scrolling lists use `focus-inset` and bordered cards `focus-visible:border-accent`, since the list clips an outside outline. Chromium drops `::-webkit-scrollbar` rules on any element with `scrollbar-width`/`scrollbar-color`, which Tailwind's `scrollbar-*` utilities set, so the slim variant is `scroll-slim`.
- **Session changes** (`features/sessions/`): `work_session.files_changed` drops nothing. It bumps `changesVersion` (every mounted `ChangesPane` reloads, in the session screen or a board card's dialog) and marks the session's file diffs/images `stale` (an open one reloads in place). Never clear an entry a mounted view is showing: with nothing left to trigger a reload it spins forever, and a diff that goes back to the spinner remounts its viewer and loses the scroll. Loads of one entry are numbered so an older answer arriving late is dropped.
- **Sticky headers**: Chromium sticks `top-0` below the scroll container's padding, so the content scrolling under shows through that strip. Keep the padding inside the scroller (an inner wrapper), as `ChangesPane` and the card dialog do.
- **Plans and sessions in the chat**: a plan approved to run in a session renders the session inside its card (`PlanPayload.sessionId`, fetched with `ensure` when missing, since it may be another bot's); the session's own card collapses to one line only in its `planConversationId`.
- **VM screen control**: `features/vm/TakeOverOverlay.tsx` covers the VNC canvas, so it's rendered only while the screen is view-only. The daemon sends no event when control changes, so the panel rereads the display when its window gets focus back. Guest copies arrive as noVNC's `clipboard` event (dropped while view-only); `VncViewer` writes them to the host clipboard only while its window has focus.
- **UI errors**: `ui/ErrorBoundary.tsx` wraps the window, each main-window area and every chat message. Boundaries, `window` errors and unhandled rejections go through `lib/error-report.ts` to `<dataRoot>/logs/renderer.log` (`services/logging/`); `windows/create.ts` also logs a dead or unresponsive page there and reloads the window. Read that file first when a user reports a blank window. To exercise a boundary through CDP, make a global the tree calls throw (e.g. `Intl.DateTimeFormat`); `Page.crash` exercises the reload.
- Dev: `#/dev/avatars`; `window.__milibotDev.applyWorkspaceEvent(evt)` injects WS events (app store, other stores and the query cache).
- **Locales**: one JSON per top-level key (`i18n/locales/<lang>/<key-in-kebab>.json`, small keys in `common.json`), merged by `locales/<lang>/index.ts`; a new top-level key needs its file in both languages and an entry in both `index.ts`. Import `@/i18n/locales/<lang>`, never a JSON file; the key types come from pt-BR.
- **Lint**: the React Compiler rules (`react-hooks/*`) are errors. Latest-value refs are written in `useLayoutEffect` or replaced by `useEffectEvent`; a copy of a prop being edited is `useDraft(value)`; `Date.now()` in render is `useNow(ms)`; an icon looked up at render goes through `createElement`. A disable names its reason (`-- …`).
- **Component tests** (`dom` project, `src/test/setup.ts` switches i18n to English): mock heavy screens with `vi.mock` (factories through `vi.hoisted`) and drive the real app store; store tests that need no DOM stay `*.test.ts` with `@/api/daemon` mocked.

## Visual verification

- `MILIBOT_VM_AUTOSTART=0 MILIBOT_DATA_DIR=$D/devdata MILIBOT_SECRET_STORE=memory pnpm dev:daemon` + `MILIBOT_DAEMON_EXTERNAL=1 MILIBOT_DATA_DIR=... pnpm --filter @milibot/desktop exec electron-vite dev --remoteDebuggingPort 9333`. With `--outDir $D/out` also pass `--entry $D/out/main/index.js` and `-- --user-data-dir=$D/ud`.
- Screenshots through CDP (`Page.captureScreenshot` after `Page.bringToFront` + `Emulation.setFocusEmulationEnabled`, otherwise virtuoso lags). Never osascript/System Events (hangs asking for permission) or `screencapture` (comes out black).
- With another dev Milibot open (single-instance lock): run only the renderer in a Vite on another port and `electron .` with `ELECTRON_RENDERER_URL` and its own `--user-data-dir`.
- Notifications: main logs `[notifications] <title> — <body>`. Dropped files: CDP `Input.dispatchDragEvent` with `data.files` exercises the drop end to end.
- Setup from scratch without touching the real golden: `MILIBOT_GOLDEN_IMAGE=$D/…/debian13-golden.qcow2` (missing) + `MILIBOT_VM_BUILD=<fake>` that ends with `ln -s` to the real golden. VM screen without booting: fake `vm/system.qcow2` and `vm/data.qcow2` (`qemu-img create -f qcow2 … 40G`), `vm/config.json` and `agent.token` in the scratch data dir.
- To see the tray on a bot's XFCE, add the `systray` panel plugin and run Electron as that user with its session D-Bus.

## Packaging (`scripts/package/`; macOS arm64, Linux x64/arm64, Windows x64)

- electron-builder through its API (not Forge); version = root `package.json`. Build on the target OS and architecture (Electron and the addons come from this install; Electron's binary is downloaded into `node_modules/electron/dist` first); `--target win32-x64` cross-builds, without wine only `--dir`. Only `index.mjs` runs anything; the other modules are side-effect free and throw `PackageError` instead of exiting.
- Resources ship the official Node 24 (distro/Homebrew Node is refused; override with `MILIBOT_PACKAGE_NODE`), `daemon/` with only this platform's native addons, and `vm/` (the host CLIs bundled with esbuild, plus `vm/bin/`: the target's gvproxy and QEMU from `installHostTools`, `vm/host/src/tools/host-tools.ts`). macOS signs every nested binary with `build/entitlements.mac.plist` (also as `entitlementsInherit`, ad hoc too): QEMU needs its `com.apple.security.hypervisor`. `afterPack` fails when the `en-US`/`pt-BR` Chromium locale paks are missing. `APP_ID` (`src/main/platform/app-id.ts`) is imported by `scripts/package/config.mjs` through Node's type stripping: keep that file to plain constants with no imports.
- **Own Node instead of `ELECTRON_RUN_AS_NODE`**: the daemon runs on the runtime it is tested on (Electron's Node uses BoringSSL and the V8 memory cage, which breaks addons' external buffers), VM scripts need `node` on the PATH, and the process shows up as `node`.
- Packaged daemon: `resolveDaemonCommand()` (`daemon/manager.ts`, also used by the login item) → pure `packagedDaemon()` (`daemon/command.ts`). `daemonEnvironment` drops Electron's and the AppImage's variables and restores the pre-AppImage library paths, so QEMU never loads Electron's libraries; PATH goes under the parent's key (`Path` on Windows). In dev, `MILIBOT_NODE` + `MILIBOT_DAEMON_ENTRY` choose what Electron spawns. A daemon of another version (`daemon.json`) is replaced.
- AppImage: the login item runs `"$APPIMAGE" --start-daemon`; `--no-sandbox` only when unprivileged user namespaces are restricted. Windows: the NSIS hooks (`build/installer.nsh`) run `--stop-daemon` before install/uninstall; logoff (`session-end`) stops the daemon too.
- **DMG window**: `DMG_LAYOUT` in `scripts/package/config.mjs` sets the window size and icon positions; `build/dmg-background.png` and `@2x` (committed, merged into a HiDPI TIFF by electron-builder) come from `pnpm dmg:background` (`apps/desktop/scripts/dmg-background/`: serves `features/setup/DmgBackground.tsx` alone through the renderer's Vite config and captures it in an offscreen Electron window; `--mock <dir>` also writes previews with the icons and labels). Regenerate after changing the layout or the avatars. Finder draws the labels black or white by the system appearance, never by the background, so they sit on mid-tone plates readable in both.
- Signing and notarization are opt-in through electron-builder's `CSC_*`/`WIN_CSC_*`/`APPLE_*` variables; without them macOS is signed ad hoc and the Windows installer is unsigned.
- **Fuses** (`electronFuses` in `scripts/package/config.mjs`): no `ELECTRON_RUN_AS_NODE`, no `NODE_OPTIONS`, no `--inspect`, app only from `app.asar`, asar integrity on macOS/Windows. Anything that would need Electron as Node must use the bundled Node or a utility process. `MILIBOT_PACKAGE_INSPECT=1` builds with `--inspect` allowed (verification builds only).
- **Verifying the package** (never against the real data root; package with `MILIBOT_PACKAGE_INSPECT=1`): `env MILIBOT_DATA_DIR=$D/data MILIBOT_SECRET_STORE=memory MILIBOT_FAKE_LLM=$D/script.json MILIBOT_VM_PORT_FIRST=47800 MILIBOT_GOLDEN_IMAGE=<real versioned golden> dist/mac-arm64/Milibot.app/Contents/MacOS/Milibot --remote-debugging-port=9451 --inspect=9452`. Check that the `daemon.json` pid runs `Resources/node/bin/node Resources/daemon/main.js`. At the end stop the VM, quit the app, SIGTERM the daemon **you** started. A synchronous error dialog in main freezes CDP (`sample <pid>` shows `NSAlert runModal`).
